# `wms` — склад, который сам говорит с Wildberries

Сервис потока A. Между Wildberries и заданием больше нет очереди: воркер
опросил WB и той же транзакцией Postgres завёл задание с резервом (раздел 6.2
мастер-контекста). Рабочее место спрашивает свои задания по HTTP и видит их,
даже когда RabbitMQ лежит.

Читать перед кодом: `docs/00-master-context.md` целиком, затем
`docs/02-stream-a-wms-wildberries.md`. Расхождения контракта и схемы, которые
поток A не вправе решить сам, собраны в [FINDINGS.md](FINDINGS.md).

## Что здесь есть

| Файл | Что делает |
|---|---|
| `app/service.py` | **Транзакция раздела 6.2** — ядро. Задание, резерв, движение и событие одним коммитом |
| `app/repositories.py` | Весь SQL. Ни одного решения, ни одного вызова наружу |
| `app/postgres.py` | Пул соединений, повтор при конкуренции за строку остатка |
| `app/tasks.py` | Выдача сборщикам (`FOR UPDATE SKIP LOCKED`), скан, упаковка, отмена |
| `app/receiving.py` | Приёмка по факту, расхождения, коробки, инвентаризация |
| `app/shipments.py` | Поставки: собрать, закрыть, передать, подтвердить сверкой |
| `app/labels.py` | Этикетка из локального хранилища, готовые байты агенту печати |
| `app/returns.py` | Возвраты минимально: принять, решить |
| `app/stock_push.py` | Публикация остатка немедленно, конвейером по кабинету |
| `app/wb.py` | Единственное место, где сервис ходит в Wildberries |
| `app/secrets.py` | `secret_ref` → токен. Значение не покидает этот слой |
| `app/rate_limit.py` | 300 запросов в минуту на кабинет, окно в базе |
| `app/api.py` | Сборка приложения: заглушка потока 0 либо настоящий сервис |
| `app/mock*`, `app/state.py`, `app/fixtures.py` | Заглушка потока 0. Живёт до тех пор, пока потоки B и C на неё опираются |

Воркеры — отдельные процессы, а не потоки сервиса. Раздел 12 требует изоляции
радиуса отказа: упал опрос WB — приёмка, подбор и инвентаризация продолжают
работать.

| Воркер | Зачем |
|---|---|
| `app.workers.wb_sync` | Опрос заданий. Заменяет `gateway-sync-worker` вместе с очередью за ним |
| `app.workers.wb_labels` | Стикеры заранее, пачкой до 100, в ZPL |
| `app.workers.wb_reconcile` | Сверка статусов. Расхождение — `diverged` и алерт, не тихая запись |
| `app.workers.outbox_publisher` | События в шину, партиции и ретеншен |

## Как запустить

```bash
export DATABASE_URL=postgresql://wms:...@127.0.0.1:5432/wms
export RABBITMQ_URL=amqp://mmx:...@127.0.0.1:5672/
export WB_SIMULATOR_URL=http://127.0.0.1:8090

docker compose up -d          # сервис и четыре воркера
```

Заглушка потока 0 никуда не делась: `WMS_MOCK=true` поднимает её вместо
настоящего сервиса. Потоки B и C переключаются флагом, а не пересборкой
(правило 9.5.4).

**Переключение по одному кабинету.** `WB_SYNC_ONLY_ACCOUNTS` — список внешних
идентификаторов кабинетов через запятую. Пусто — все. Это не удобство тестов,
а требование раздела 11: первый клиент едет отдельно, остальные остаются на
боевом шлюзе, и откат — убрать кабинет из списка.

### Что означает `shadow`

Кабинет в режиме `shadow` опрашивается (`GET /api/v3/orders`) и сверяется, но
в Wildberries не пишется ничего: ни стикеров, ни поставок, ни остатков
(раздел 11, шаг 2). В `staging` и `prod` это абсолютно. Исключение одно и
требует двух независимых условий сразу: локальное окружение **и** незаданный
`WB_API_URL`, то есть отвечает симулятор стенда, где живых кабинетов нет по
построению. См. `wb.writes_allowed`.

## Тесты

```bash
export WMS_TEST_DATABASE_URL=postgresql://wms:...@127.0.0.1:5432/wms_test
export WB_SIMULATOR_URL=http://127.0.0.1:8090

python -m pytest -q
```

Тесты ядра идут против **настоящего** Postgres с применёнными миграциями: смысл
транзакции 6.2 — блокировки, триггеры проекции и `ON CONFLICT`, и на заглушке
их нет. Без `WMS_TEST_DATABASE_URL` они пропускаются, говоря об этом вслух.

> Job `tests` в общем CI поднимает Postgres только для миграций, поэтому там
> эти тесты сейчас пропускаются. Заявка потоку 0 — находка 4 в FINDINGS.md.

Полный прогон стенда (16 проверок раздела 9.6) — в `tests/full-run/`:

```bash
python -m pytest -m stream_a      # только то, что чинит поток A
```

## Что держит инварианты

Не дисциплина кода, а то, что нельзя обойти:

- **База.** `stock_move` append-only, `stock_balance` пересчитывается
  триггером-проекцией, прямая запись в баланс запрещена. Причина отмены,
  комментарий коробки, подпись передачи — ограничения схемы, а не соглашения.
- **Тесты.** Конкурентный резерв десятью процессами, запрет исходящих вызовов
  на время транзакции, проверка отсутствия открытых транзакций во время
  разговора с брокером, соответствие всех маршрутов контракту из репозитория.
- **Метрики.** Удержание блокировки, задержка публикации остатка, сборки без
  остатка, расхождения с WB, обработанное каждым воркером за минуту. Молчащий
  воркер считается сломанным (инвариант 14).
